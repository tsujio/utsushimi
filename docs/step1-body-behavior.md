# Step 1 身体状態・自動運動・表情の仕様

## 位置づけ

この文書はStep 1のローカルな身体反応モデルを定義する。KOKOROが担う人格、学習、長期記憶、高度な意思決定とは分離する。実装状況・実機検証状況は[ファームウェア](../firmware/main/README.md)、開発順序は[ロードマップ](roadmap.md)、責務分離は[アーキテクチャ](architecture.md)を参照する。

**実装状況：** 現行ファームウェアは乾燥度・欲求に基づく瞬きモデルであり、以下の自動運動モデルへの移行は未実装。既存の表情と瞬きのホスト試験結果を、新モデルの検証済み結果と混同しない。

## 処理モデル

```text
TouchSensor / PettingDetector
  | touch_started / touch_ended / petting_detected
  v
Stimulus (holding) ----> BodyState (valence)
                              |
                              v
                         Expression (valence -> eyelids)
                              |
                              +-------------------+
                                                  |
Automatic Movement (blink generation + animation) |
                  |                               |
                  +-------------------------------+
                                  |
                                  v
                              EyeRenderer
```

入力・意味イベント・身体状態・表情・自動運動・描画を分離する。表情と瞬きは独立して進行し、描画時に合成する。センサー処理を止めない非ブロッキング設計とする。

### 概念の境界

- **BodyState**：再起動時に初期化する一時的な身体・情動状態。Step 1では `valence` のみ。
- **Expression**：身体状態を継続的な表情へ変換する。撫でイベントから直接「目を細める行動」を起動しない。
- **Automatic Movement**：欲求や明示的な意思決定を必要とせず生成する運動。Step 1では瞬きのみ。将来の微小眼球運動・呼吸様運動などを想定するが、実装対象外。
- **Desire / Decision / Action**：将来、欲求や目標に基づく行動を扱う概念として維持する。Step 1で空の欲求層・汎用行動判断エンジンは実装しない。
- **EyeRenderer**：身体状態・乱数・時刻から独立し、表情と運動から渡された幾何パラメータを描画する。

Automatic Movementは運動の**発生経路**を表す。同じ身体能力を将来KOKOROから明示的に指示できる余地を残すが、競合時の調停規則はStep 1で決めない。

## 身体状態と刺激

- `valence` (`v`)：-1〜1。負は不快、正は快。KOKOROの永続的な感情・人格ではない。
- `holding` (`h`)：継続接触の刺激状態。 `touch_started` / `touch_ended` で更新する。
- `petting_detected`：撫で動作を表す離散イベント。継続接触そのものとは区別する。
- `eye_dryness`、`eye_moisture_need`、`boredom` はStep 1に導入しない。瞬きによる乾燥回復や乾燥由来の不快も扱わない。

快・不快の時間発展は、乾燥項を除いた次式とする。

```text
dv/dt = -v / comfort_decay_time + holding_sensitivity * h
petting_detected: v = clamp(v + petting_sensitivity, -1, 1)
```

`valence` は-1〜1に制限する。起動時は0。保持刺激と撫でイベントによる変化、および中立への指数的な減衰は維持する。状態はRAMのみで保持し、再起動時に初期化する。

## Automatic Movement：瞬き

瞬きは身体の乾燥・欲求・情動から独立した、自動生成される離散的運動とする。各動作が独立した待機タイマーを持つ方式ではなく、共通の経過時間更新から確率的な開始判定とアニメーション進行を行う。

以下の既存の動作仕様を維持する。

- `blink_interval = 5秒`：瞬き行動の**開始から次の開始までの実測平均**の目標。
- `blink_duration = 150ms`：単発の閉じ始めから開き終わりまで。閉30%・閉眼保持20%・開50%（既定45/30/75ms）。
- 瞬き開始時に10%の確率で二連瞬きを選び、それ以外は単発とする。二連は1つの運動で、1回目が開き終わってから2回目が閉じ始めるまで100ms（既定の合計400ms）。
- 運動終了後1秒は新たな瞬きを開始しない（二連内部の2回目は対象外）。
- 確率判定・アニメーションとも非ブロッキング。処理周期が変わっても発生率が大きく変わらない経過時間ベースの確率を用いる。
- 長時間停止後に過去の瞬きをまとめて再生しない。

**未決定：** 瞬きの確率モデルを「一定発生率」「前回の瞬きからの経過時間に応じた発生率」「次回時刻の抽選」のどれにするか。平均5秒を満たす係数は単発・二連・不応期を含めたホストシミュレーションで較正する。発生率を `valence` で変調するかどうかも未決定であり、Step 1の初期実装では独立を暫定方針とする。

## Expression：快状態の表情

正の `valence` は目を細める表情として表現する。負の `valence` 専用の形状はStep 1で確定しない。

```text
target_openness = 1 - squint_strength * max(0, v)
d(expression_openness)/dt =
    (target_openness - expression_openness) / expression_response_time
```

表情の追従は瞬きとは独立して進行する。表情は上下まぶたの幾何パラメータ、瞬きは開眼率としてEyeRendererに渡し、形状を合成する。撫でイベントは`valence`を変えるだけで、表情アニメーションを直接起動しない。

## 採用した快のまぶた形状

2026-10-19のユーザーによる実機確認を受け、上下の弧を揃えたまぶた形状（比較時のB）を採用する。比較用の切り替え・周期入力・二段階追従は削除する。

表情の追従から `q = 1 - expression_openness` を求め、上下まぶたの幾何パラメータとして描画へ渡す。円形の白目と瞳を同じマスクで覆い、上まぶたを少し下げ、下まぶたの中央を持ち上げる。上下の境界は共通の楕円弧を上下移動して作り、曲率を揃える。瞳自体の位置やサイズは変えず、まぶたで自然に隠す。

描画時のまぶた量は0.5で飽和させ、弧の交差を避ける。`squint_strength` の初期値は0.5、表情追従の時定数は200msを維持する（目標の約95%に達するまで約600ms）。負の快不快専用の形状、眉毛・口・ハイライトは追加しない。

身体状態・表情追従は `BodyBehavior`、幾何パラメータによる形状生成は `EyeRenderer` が担当する。瞬きの開眼率は別に渡し、まぶた形状全体を縦に閉じる。描画層へ時刻・乱数・快不快を持ち込まない。


## 調整可能な振る舞いパラメータ

乾燥関連の2項目を削除し、次の7項目を維持する。値は初期候補であり、実機で調整する。

| パラメータ | 初期値 | 意味 |
| --- | ---: | --- |
| `blink_interval` | 5 s | 瞬きの平均開始間隔の目標 |
| `blink_duration` | 150 ms | 単発瞬きの時間 |
| `comfort_decay_time` | 20 s | `valence` が中立へ戻る時定数 |
| `petting_sensitivity` | +0.35 / event | 撫でによる快方向の変化 |
| `holding_sensitivity` | +0.02 / s | 保持刺激による快方向への変化率 |
| `squint_strength` | 0.5 | `v=1` での目の細まりの強さ |
| `expression_response_time` | 200 ms | 表情追従の時定数 |

二連確率・不応期・内部間隔は当面公開調整パラメータに含めない。

## 更新・実装上の制約

- 身体状態と入力APIは同一タスクが所有する。入力イベントはモデル時刻で適用する。
- 内部積分は既存の10ms固定刻みを維持する。1回の`advance`は100msまで処理し、超過時間は捨てる。通常稼働時の確率較正とは区別する。
- 乱数源は外部から注入し、ホスト試験で再現可能にする。描画層には乱数や`valence`を渡さない。
- `BodyBehavior` は時間進行・入力・状態を管理する。Automatic Movementの責務は分離する方向だが、Step 1では汎用登録機構やスケジューラーを導入しない。
- センサーから描画を直接呼ばない。入力源がない段階ではイベントキューを先回りして導入しない。

## 未決定・検証事項

- 瞬き発生率の時間依存モデルと係数、平均開始間隔5秒のホスト再較正。
- Automatic Movementを独立モジュールとする具体的なAPI・クラス境界（責務分離は採用、過剰な汎用化は避ける）。
- `valence`による瞬きの変調は当面行わない暫定方針を最終確定するか。
- 保持と判定する電極組み合わせ、撫での閾値・方向・時間条件、イベントの間引き。
- タッチ取得タスクとの接続方式、必要になった場合のイベントキュー容量・過負荷処理。
- 実機での表情・瞬きの自然さ、ちらつき、入力応答、長時間稼働時の瞬き間隔。
- 負の`valence`専用の目の形は未定。

実装・ホスト試験・実機試験の完了は、それぞれ別に記録する。
