# Step 1 身体状態・自動運動・表情の仕様

## 位置づけ

この文書はStep 1のローカルな身体反応モデルを定義する。KOKOROが担う人格、学習、長期記憶、高度な意思決定とは分離する。実装状況・実機検証状況は[ファームウェア](../firmware/main/README.md)、開発順序は[ロードマップ](roadmap.md)、責務分離は[アーキテクチャ](architecture.md)を参照する。

**実装状況：** 自動運動による瞬きと、快不快・表情のモデルを実装している。検証条件・結果と実機での未確認事項は[ファームウェアの確認状況](../firmware/main/README.md#確認状況)を参照する。

## 処理モデル

```text
TouchSensor / PettingDetector
  | touch_started / touch_ended / petting_detected
  v
Stimulus (holding) ----> BodyState (valence)
                              |
                              v
                         Expression (valence -> eyelids)
                              |
                              +-------------------+
                                                  |
Automatic Movement (blink generation + animation) |
                  |                               |
                  +-------------------------------+
                                  |
                                  v
                              EyeRenderer
```

入力・意味イベント・身体状態・表情・自動運動・描画を分離する。表情と瞬きは独立して進行し、描画時に合成する。センサー処理を止めない非ブロッキング設計とする。

### 概念の境界

- **BodyState**：再起動時に初期化する一時的な身体・情動状態。Step 1では `valence` のみ。
- **Expression**：身体状態を継続的な表情へ変換する。撫でイベントから直接「目を細める行動」を起動しない。
- **Automatic Movement**：欲求や明示的な意思決定を必要とせず生成する運動。Step 1では瞬きのみ。将来の微小眼球運動・呼吸様運動などを想定するが、実装対象外。
- **Desire / Decision / Action**：将来、欲求や目標に基づく行動を扱う概念として維持する。Step 1で空の欲求層・汎用行動判断エンジンは実装しない。
- **EyeRenderer**：身体状態・乱数・時刻から独立し、表情と運動から渡された幾何パラメータを描画する。

Automatic Movementは運動の**発生経路**を表す。同じ身体能力を将来KOKOROから明示的に指示できる余地を残すが、競合時の調停規則はStep 1で決めない。

## 身体状態と刺激

- `valence` (`v`)：-1〜1。負は不快、正は快。KOKOROの永続的な感情・人格ではない。
- `holding` (`h`)：継続接触の刺激状態。 `touch_started` / `touch_ended` で更新する。
- `petting_detected`：撫で動作を表す離散イベント。継続接触そのものとは区別する。
- `eye_dryness`、`eye_moisture_need`、`boredom` はStep 1に導入しない。瞬きによる乾燥回復や乾燥由来の不快も扱わない。

快・不快の時間発展は次式とする。

```text
dv/dt = -v / comfort_decay_time + holding_sensitivity * h
petting_detected: v = clamp(v + petting_sensitivity, -1, 1)
```

`valence` は-1〜1に制限する。起動時は0。保持刺激と撫でイベントによる変化、および中立への指数的な減衰は維持する。状態はRAMのみで保持し、再起動時に初期化する。

## Automatic Movement：瞬き

瞬きは身体の乾燥・欲求・情動から独立した、自動生成される離散的運動とする。各動作が独立した待機タイマーを持つ方式ではなく、共通の経過時間更新から確率的な開始判定とアニメーション進行を行う。

以下の既存の動作仕様を維持する。

- `blink_interval = 5秒`：瞬き行動の**開始から次の開始までの実測平均**の目標。
- `blink_duration = 150ms`：単発の閉じ始めから開き終わりまで。閉30%・閉眼保持20%・開50%（既定45/30/75ms）。
- 瞬き開始時に10%の確率で二連瞬きを選び、それ以外は単発とする。二連は1つの運動で、1回目が開き終わってから2回目が閉じ始めるまで100ms（既定の合計400ms）。
- 運動終了後1秒は新たな瞬きを開始しない（二連内部の2回目は対象外）。
- 確率判定・アニメーションとも非ブロッキング。処理周期が変わっても発生率が大きく変わらない経過時間ベースの確率を用いる。
- 長時間停止後に過去の瞬きをまとめて再生しない。

### 発生確率モデル

不応期が終了した時点を `t = 0` とし、以後の確率的待機時間 `W` に形状パラメータ `k = 2` のワイブル分布を採用する。ハザード関数は `h(t) = (k / λ) (t / λ)^(k-1)` とし、時間経過とともに瞬きが発生しやすくなる。形状 `k` は内部定数であり、公開調整パラメータにはしない。

10ms更新時の条件付き発生確率は次式とする。

```text
P(t, dt) = 1 - exp(-(((t + dt) / λ)^k - (t / λ)^k))
```

不応期・動作中は新規の瞬き判定を行わない。瞬きの発生率はStep 1では `valence`、`holding`、その他の身体状態に依存させない。

`blink_interval` は瞬きの開始から次の開始までの平均目標値とする。単発確率90%、二連確率10%、各動作長150ms・400ms、不応期1秒の初期設定では、平均動作長 `E[D] = 0.9 × 0.150 + 0.1 × 0.400 = 0.175秒`。ワイブル分布の平均 `E[W] = λ Γ(1 + 1/k)` を用い、

```text
λ = (blink_interval - E[D] - 1.0) / Γ(1 + 1/k)
```

とする。既定の `blink_interval = 5秒`、`k = 2` では `λ ≈ 4.316秒`。この値は理論値であり、10ms離散化を含む実測平均と分布はホストシミュレーションで確認する。動作長・二連確率・不応期を変更する場合は `E[D]` も再計算する。

時間パラメータは有限な0.01〜3600秒、感度・強度は有限な0〜1とする。加えて `blink_interval > E[D] + 1秒` を厳密に満たす必要があり、等号も不正とする。動作時間はマイクロ秒へ丸め、その実際の長さから `E[D]` を計算する。`BehaviorParameters::valid()` で検査し、ファームウェアは起動時に不正設定をエラーとして停止する。ライブラリの `BodyBehavior` は不正設定の全項目を既定値へ戻す防御を持ち、`used_default_parameters()` で検出できる。

起動時は待機時間0から開始する。不応期の終了をまたぐ更新では終了後の区間だけを確率判定し、終了時刻ちょうどでは判定しない。開始時刻は10ms格子に量子化されるため、連続分布の理論平均に数ms程度の差が生じ得る。極端に短い正の待機時間では、この量子化の影響が相対的に大きくなる。

## Expression：快状態の表情

Expressionは通常・心地よいの2状態を持ち、初期状態は通常とする。

| 現在の状態 | 条件 | 次の状態 | 目標開眼率 | 遷移時間 |
| --- | --- | --- | --- | --- |
| 通常 | `valence >= 0.3` | 心地よい | 0.5 | 250ms |
| 心地よい | `valence <= 0.15` | 通常 | 1.0 | 400ms |

閾値の間では現在の状態を維持する。状態は遷移の開始時に切り替え、開眼率は連続的に変化させる。追加の撫でで快が増えても、心地よい状態の目標は0.5のままで遷移を再起動しない。負のvalenceも通常の表情とし、不快専用の形状は追加しない。

遷移開始時の開眼率を `start`、目標値を `target`、経過時間を `elapsed`、遷移時間を `duration` として、次のsmoothstep補間を用いる。

```text
u = clamp(elapsed / duration, 0, 1)
expression_openness = start + (target - start) * u*u*(3 - 2*u)
```

指定時間で目標値に到達する。遷移中に目標状態が変わった場合は、現在の開眼率を新しいstartとして経過時間を0に戻す。残りの距離によらず、新しい方向の遷移時間を使用する。位置は連続し、反転時の速度の連続性までは保証しない。

既存の10ms内部更新で身体状態を進めた後、閾値を評価して、その更新区間の時間を表情に積算する。実入力から状態評価までは最大1内部刻みの量子化がある。撫でイベントはvalenceだけを更新し、表情アニメーションを直接起動しない。表情と瞬きは独立して進行し、EyeRendererへ幾何パラメータを渡して合成する。

## 採用した快のまぶた形状

上下の弧を揃えたまぶた形状を採用する。この形状はユーザーによる実機確認済み。

表情の追従から `q = 1 - expression_openness` を求め、上下まぶたの幾何パラメータとして描画へ渡す。円形の白目と瞳を同じマスクで覆い、上まぶたを少し下げ、下まぶたの中央を持ち上げる。上下の境界は共通の楕円弧を上下移動して作り、曲率を揃える。瞳自体の位置やサイズは変えず、まぶたで自然に隠す。

細目では目尻側の上下境界を同量持ち上げ、頬が上がる印象を表現する。目の中心から外側へ正規化した距離を `u`（0〜1）として、持ち上げ量は `8px × (lower_lid / 0.5) × u²(3−2u)` とする。中央・目頭・通常時は持ち上げず、左右は鏡像対称。上下境界の間隔を保ち、円の輪郭と瞳のクリップは維持する。8pxは実機調整用の暫定値で、見た目の確認は未完了。

描画時のまぶた量は0.5で飽和させ、弧の交差を避ける。通常のまぶた量は0、心地よい状態は0.5であり、その間を補間する。負の快不快専用の形状、眉毛・口・ハイライトは追加しない。

身体状態・表情追従は `BodyBehavior`、幾何パラメータによる形状生成は `EyeRenderer` が担当する。瞬きの開眼率は別に渡し、まぶた形状全体を縦に閉じる。描画層へ時刻・乱数・快不快を持ち込まない。


## 調整可能な振る舞いパラメータ

次の5項目を調整できる。値は初期候補であり、実機で調整する。

| パラメータ | 初期値 | 意味 |
| --- | ---: | --- |
| `blink_interval` | 5 s | 瞬きの平均開始間隔の目標 |
| `blink_duration` | 150 ms | 単発瞬きの時間 |
| `comfort_decay_time` | 20 s | `valence` が中立へ戻る時定数 |
| `petting_sensitivity` | +0.35 / event | 撫でによる快方向の変化 |
| `holding_sensitivity` | +0.02 / s | 保持刺激による快方向への変化率 |

表情の閾値・開眼率・遷移時間は上記の合意値を `ExpressionSettings` に集約し、振る舞いの感度パラメータとは分離する。二連確率・不応期・内部間隔は当面公開調整パラメータに含めない。

## 更新・実装上の制約

- 身体状態と入力APIは同一タスクが所有する。入力イベントはモデル時刻で適用する。
- 内部積分は既存の10ms固定刻みを維持する。1回の`advance`は100msまで処理し、超過時間は捨てる。通常稼働時の確率較正とは区別する。
- 乱数源は外部から注入し、ホスト試験で再現可能にする。描画層には乱数や`valence`を渡さない。
- `BodyBehavior` は入力イベント・身体状態・共通の10ms時間進行を管理する。`Expression` は `valence` から表情を生成する。`Automatic Movement` は瞬きの確率的な発生判定、不応期管理、アニメーション進行を担当する独立モジュールとする。具体的には `AutomaticBlink` が発生判定と不応期を管理し、既存の `Blink` がアニメーションを担う。`Expression` は `body_behavior.*` 内の小さなクラスとする。Step 1では汎用登録機構やスケジューラーを導入しない。
- センサーから描画を直接呼ばない。入力源がない段階ではイベントキューを先回りして導入しない。

## タッチ入力と撫で判定（暫定）

3電極を独立して校正・接触判定し、全電極の校正が完了した走査だけを身体入力に使う。`PettingDetector` は確定接触マスクと走査時刻を受け取り、A→B→CまたはC→B→Aを一度ずつ検出する。生の値は身体・描画層へ渡さない。

| 条件 | 暫定設定 |
| --- | --- |
| 起動・成立・失敗後の再受付 | 全電極の離脱が100ms継続 |
| 隣の電極の接触開始まで | 100〜1000ms（両端を含む） |
| 最初から最後の接触開始まで | 最大2000ms |
| 測定欠落 | エラーまたは150ms超で進行を破棄 |

隣接電極の重なり、移動中の短い非接触は許容する。最後の電極に触れる時点で最初の電極は離れている必要がある。同時開始・途中の逆戻り・Bからの開始・3枚を覆う接触は成立しない。成立後に触れ続けても重複生成せず、次の撫でには全離脱が必要。単に手を置く動作と順次移動が同じ接触系列になった場合は区別できない。時間設定は `touch/petting_detector.h` に集約し、電極形状・間隔とともに実機調整する。

保持刺激は暫定的に「いずれか1枚以上が接触」とし、電極数で加算しない。長さ1の最新状態キューを身体タスクが読み、保持の変化を `touch_started` / `touch_ended` にする。500ms超の未更新は保持解除とする。複数電極の継続接触から手を置く動作を分類する正式な条件は未確定。

撫では方向と測定時刻を長さ8のキューで渡す。満杯なら新しいイベントを警告して破棄し、500ms超の古いイベントも破棄する。身体タスクは非ブロッキングで取り出し、両方向とも既存の `petting_detected` として快を加算する。身体状態の計算と通常の瞬きは独立に維持し、表情は上記の2状態モデルを使用する。これらのキュー設定は入力を溜めて再生しないための実装上の暫定値。

検出器の両方向・接触重複・誤系列・時間境界・再受付・欠落と、保持／撫での身体反応はホスト試験対象。Aの接触判定は試作条件で実機確認済み。B/Cの測定、3電極の撫で検出、実入力から表情への連動は実機未検証。

## 基準値の追従（暫定）

`ContactDetector` は起動時校正後、電極ごとに基準値を更新する。接触閾値・離脱閾値・撫での時間条件は変更しない。`ContactSettings` に以下の調整値を集約する。

- 未接触で、現在の基準値との差が±400カウント以内。
- 連続サンプル間の変化が100カウント以内。
- 上記が2秒継続してから、時定数20秒の指数平滑化で追従する。更新量は最大10カウント/秒。
- 接触中・接触の確定待ち・急変・追従範囲外・測定欠落では追従を止め、安定時間をリセットする。離脱後も改めて2秒待つ。
- 0の測定値は校正後も無効とし、接触判定と基準値の更新に使用しない。欠落時間をまとめて積分しない。

大きな変化を非接触と決めつけないため、±400を超えるずれは自動復旧の対象外とする。手を離してRESETし再校正する。非常にゆっくりした手の接近や弱い接触と環境ドリフトは、この観測だけでは完全に区別できない。配線・電源条件を変えた際の追従値は実機で調整する。

ホスト試験では6分で±720カウントのドリフトに対して残差50未満、ドリフト後の接触と長押し、離脱直後の凍結、測定停止・0・急変での更新抑制を検証する。ユーザーから追従版の実機動作は良好との報告がある。追従残差・誤検出率の定量評価と環境差の検証は未完了。
