# 開発ロードマップ

## Step 1 — 身体的コミュニケーション

目の表示・瞬き、3電極の接触・撫で検出、表情連動と接触時の視線反射を実装しています。所有者は試作機の12時間稼働後にも、瞬き・撫でへの表情反応・接触時の視線移動を確認しています。個々の電極感度、両方向の撫で、条件を変えた再現性などの評価は残っています。[ファームウェアの確認状況](../firmware/main/README.md#確認状況)を参照してください。ハードウェア条件は[ハードウェア](hardware.md)、責務と互換性は[アーキテクチャ](architecture.md)に集約します。

完了条件は、**電源を接続すると目を開き、撫でられると目で反応すること**です。USB-Cでの動作、丸い白目・黒い瞳の2つの目、非ブロッキングの瞬きと視線移動、外部静電容量タッチ検出、意味イベント `petting_detected`、ネットワークやKOKOROなしでの自然な目の反応を確認します。

マイク、スピーカー、モーター、カメラ、LLM連携、長期記憶はこのステップの対象外です。

### Step 1.1 — 画面表示

- 公式Rev2.0デモを実行し、結果を記録する。
- 対応するV2ドライバー・リセット経路でディスプレイを初期化する。
- 黒背景に丸い白目・黒い瞳の左右2つの目を表示する。静止状態を基本とし、現在は瞬きも追加済み。

USB-C給電で、正しい向きの目を安定して表示できれば完了です。メーカーのデモ確認と、UTSUSHIMIの最小表示は別々の検証項目として扱います。

実装・検証の準備項目（開発環境、書き込み、公式デモ表示はユーザー報告で確認済み。詳細ログと独自表示の実機確認は引き続き必要）：

1. アーキテクチャに記載した固定版V2デモと再現用構成を選び、メモリ・パーティション設定の注意点を確認する。
2. 開発用ホスト、ツールチェーン構成、USBへのアクセス方法を決め、実装作業の際に選定した環境を導入する。
3. 確認済み基板とデータ通信対応USB-Cケーブルを用意し、書き込み・ログ取得とBOOT/RESETによる復旧手順を確認する。
4. 対応するデモをビルド・書き込みし、リセット動作、表示の向き・色、Flash／PSRAM認識、エラーを記録してから、最小の目の表示を実装する。

電極の校正や将来の音声・台座部品の選定が未完了でも、この表示のみのマイルストーンは進められます。

### Step 1.2 — 目のアニメーション

- 自然な単発・二連のランダムな瞬きと視線移動を追加する。瞬きと接触開始時の上方向への視線反射は実装済みで、試作機での継続動作を確認済み。
- アーキテクチャの目のモデルに従い、視線・開き具合・瞳の大きさをパラメータ化する。
- 基本的な表情変化を追加する。

アニメーションが滑らかに遷移し、ほかの処理を妨げなければ完了です。フレームレート、バッファ方式、時間設定は先に固定せず、測定して決めます。

Step 1.2〜1.4にまたがる身体状態・自動運動としての瞬き・快不快に応じた表情の合意仕様は[Step 1 身体反応モデル](step1-body-behavior.md)に記載します。身体反応モデルは実装・ホスト検証済みです。実電極の意味イベント生成・接続は実装済みで、3電極と身体反応の実機検証は未完了です。

### Step 1.3 — タッチ検出

電極Aの生測定値と接触・離脱をシリアルログで観察する診断機能を実装しています。接触・離脱に対応する測定値の変化と、表示・瞬きの見た目に変化がないことをユーザーが実機で確認済みです。測定条件・数値・残る制約はファームウェア文書の確認状況に集約しています。[確認手順](../firmware/main/README.md#電極aの初期動作確認)に従って非接触・接触を比較します。電極Aの起動時校正・接触開始／終了のログ判定は試作条件で実機確認済みです。A/B/Cの測定、両方向の撫で判定と身体反応への接続は実装済みです。判定はホスト試験済みで、試作の撫で・表情連動も所有者が確認済みです。個々の電極感度と両方向の検出精度は未評価です。

- 3電極すべての静電容量を測定する。初期のデバッグは1電極から始めてもよい。
- 試作機で基準値・閾値・フィルタリングを調整する。
- 接触開始・終了と、撫でる方向・時間的パターンを検出する。

未接触時のノイズ、接触の重なり、手を置いた状態も確認し、接触・離脱と両方向の撫で動作を、統合に十分な安定性で区別できれば完了です。閾値と時間の具体値は実測で決めます。

### Step 1.4 — 身体反応

- `petting_detected` を含むタッチ由来の意味イベントを、`Behavior` を介して目の表情へ接続する。
- 撫でへの反応、通常の瞬き、通常表情への復帰を調整する。
- KOKOROやネットワーク接続なしでローカルに動作させる。

繰り返し撫でた場合や使用予定のUSB電源での動作を含め、試作機が上記のStep 1完了条件を満たせば完了です。試験条件と残る制約を記録します。

## Step 2 — 音声コミュニケーション（現在の対象）

聴覚と、単純な非言語の発声を追加します。

- マイク
- ウェイクワード・名前の認識
- 音源方向推定
- 名前を呼ばれた方向へ視線を向ける
- スピーカー
- 鳴き声・非言語音

この段階では自然言語理解は不要です。

### Step 2.1 — 最小音声出力

MAX98357A×1と4Ω 3Wスピーカー×1を使い、外部音声ファイルなしで440Hz・200msの電子音を生成します。既存のStep 1機能を維持します。マイク入力、方向推定、ウェイクワード、TTS、LLMは今回の対象外です。後続の聴覚・非言語音の実装は別途進めます。

- [x] V2回路図とIC仕様を照合し、既存機能と競合しない暫定GPIO案を記載。
- [x] 独立モジュール、非ブロッキング要求キュー、専用送信タスク、ソフトウェア音量、明示的な単発テスト設定を実装。
- [x] ESP-IDF v5.5.6で通常／音声テスト設定のビルド、既存のホスト回帰試験と波形試験に成功。
- [ ] 購入モジュールのSD/GAIN回路と電源余裕を確認。
- [x] 所有者が実機でスピーカーからの出音を確認。200ms・初期振幅1%での聴感は未確認。
- [x] 配置を離した2秒・振幅5%の有音データ送信中に、出音を所有者が確認し、C保持・身体更新・描画・瞬きが継続することを提供ログで確認。
- [ ] 発音中の新規接触・離脱・撫で反応、条件を変えた再現性を実機確認。残る測定値低下と検証条件は[ファームウェア](../firmware/main/README.md#音声出力の検証状況)を参照。

完了条件はビルド成功、音量を変えられる短音出力、既存機能との共存、再現可能な配線・試験手順です。資料上の電気的整合性と実機の成功を区別します。[配線・制約](hardware.md#step-21max98357aの音声出力)と[実行手順](../firmware/main/README.md#step-21音声テスト)を参照してください。Step 1に残る実機調整項目を完了扱いにはしません。

### Step 2.2 — マイク1個の音声取得とRMSログ

INMP441×1から左チャンネルを継続取得し、約100msごとにDC除去RMSとdBFSをログ出力します。Step 1とStep 2.1を維持します。認識・ウェイクワード・方向推定・録音保存・マイク2個対応は対象外です。

- [x] 所有者指定の配線、約100kΩのSD–GND抵抗、約3.3VのVDD測定を記録。
- [x] I2S0 TX/RX同時確保・共有クロック・無音送信・専用入力タスク・RMS計算を実装。
- [x] 24bit復号、DC除去、既知振幅・最大振幅のホスト試験を追加。
- [x] ホスト試験とESP-IDF v5.5.6の入力のみ／電子音併用／入力無効のTXのみの3構成のビルドに成功。
- [x] 所有者が静かな区間に対する発声・3回の拍手のRMS上昇と電子音の出音を確認。提供ログで電子音の送信前後をまたぐ約16.1秒のRMS出力、入力スタック最小空き6124バイト、提示区間に受信エラー・再起動がないことを確認。
- [x] 所有者が今回の構成で瞬き・接触時の上目・撫での笑顔の基本動作を確認。
- [ ] 長時間安定性とタッチ測定値変化・個別の検出精度を評価。起動後約12分の提供ログでも取得・描画とA→B→Cの接触・離脱・撫での身体反応への接続が継続。提示区間に受信エラー・再起動はなく、入力スタック最小空きは5916バイトですが、全区間のログ・ヒープ推移と30分以上の評価は未確認。

完了条件は上記ビルド・試験と実機での取得・共存確認です。[配線](hardware.md#step-22inmp441マイク1個)と[確認手順](../firmware/main/README.md#step-22音声入力とrmsログ)を参照してください。Step 2.1の未検証項目は引き続き残します。

## Step 3 — 睡眠／電源状態／覚醒

身体の低消費電力状態と、外部刺激による覚醒を導入します。

- Sleep（睡眠）、Aware（周囲を認識）、Active（活動）などの身体状態を検討する。
- ESP32-S3のDeep Sleepを含む省電力制御と復帰動作を検証する。
- 起床刺激の候補は、人が近づく、名前を呼ぶ、撫でる。採否・センサー・具体的な起床条件はこのステップで決める。
- 基板全体の待機消費電力、復帰に利用可能な端子と周辺回路、復帰後の身体反応を確認する。

KOKORO側の記憶整理・定着はこのステップの対象外とし、記憶／KOKOROの段階以降に検討します。

## Step 4 — 身体

本体の電子部品・配線を固定し、筐体に収めて一体の身体として完成させます。

- ブレッドボード等の仮配線を本体内の安定した実装に置き換える。
- ディスプレイ、タッチ電極、マイク、スピーカー、睡眠・覚醒に必要な部品を筐体へ統合する。
- 本体は約100 × 100 × 100 mm以内を想定し、分解・保守できる構造とする。
- 後付けのカメラモジュール用に、取り付け位置・開口部または交換式パネル・配線経路・電源と通信の拡張余地を確保する。
- 回転・移動台座との着脱・給電を見越して、接続部分の構造を検討する。

カメラの直接接続か専用マイコン方式か、モジュールの詳細仕様は未決定です。筐体を確定する前に実装可能性と必要なスペースを確認し、視覚機能の実装自体はStep 5で行います。

## Step 5 — 視覚

カメラによる知覚を追加します。

- カメラ
- 人物検出
- 顔の検出・位置推定
- 表情検出

視覚を音源方向、身体の回転、記憶と組み合わせ、人の方を見ながらやり取りできるようにします。


筐体の交換可能なカメラ用領域を利用し、カメラを追加します。接続方式・処理分担・モジュール構成は実装時に検証して決めます。

## Step 6 — 回転

交換可能な外部回転台座を追加します。

- 台座側の独立したMCU
- 本体とのBLE通信
- モーター
- エンコーダ
- 360度を超える連続回転
- 給電用スリップリング

名前を呼ばれたときの典型的な動作は、音の方向を見る、反応する、話者の方向へ身体を回す、視線を中央へ戻す、という流れです。視覚で得た人物・顔の位置も、回転の入力として活用することを検討します。

## Step 7 — 言語コミュニケーション

自然言語による会話を追加します。

- STT（音声認識）
- LLM（大規模言語モデル）
- TTS（音声合成）

負荷の大きいAI処理はESP32ではなく、KOKORO側の基盤やクラウドで実行します。

会話を視線、表情、発声、動きと組み合わせます。

## Step 8 — 記憶／KOKORO

KOKORO側に永続的な記憶を導入します。

記憶の分類には以下を含みます。

- 作業記憶
- エピソード記憶
- 意味記憶
- 習慣・好み・関係性

長期記憶は特定のUTSUSHIMIの身体ではなく、KOKOROに属します。

将来は関連する記憶を意味に基づいて検索し、言語処理や意思決定に利用できるようにします。すべての生イベントを永久保存するのではなく、記憶の定着、段階的な抽象化、忘却を検討します。

## Step 9 — 移動

交換可能な移動台座を追加します。

- 独立したコントローラー
- BLEなどによる通信
- 前進・後退
- 旋回
- 停止
- 必要に応じたバッテリー・電源状態の取得

移動は本体に恒久的に組み込まず、外部の身体能力として扱います。
