# ファームウェア

## 実装範囲

黒背景に丸い白目と丸い黒い瞳を左右に表示し、ランダムに瞬きします。瞳を少し内向きに置いた、かわいらしい記号的な表情です。Step 1.1の表示、Step 1.2〜1.4の身体反応モデル（快不快・自動運動としての瞬き・表情）を実装しています。A/B/Cの生測定ログ・校正・接触判定、両方向の撫で検出と保持・撫でによる表情連動を実装しています。B/Cと表情連動は実機未検証です。電極Aの接触・離脱判定は試作条件で実機確認済みです。視線アニメーションは未実装で、Step 1全体の完了を意味しません。

- `app_main.cpp`：起動・メモリ情報ログ、表情状態の更新、独立した表示タスク。
- `behavior/body_behavior.*`：`BodyState`、`Stimulus`、表情追従を行う `Expression` と、共通時計・イベントを管理する `BodyBehavior`。ESP-IDF・描画に依存しません。
- `behavior/automatic_blink.*`：身体状態と独立したワイブル発生判定・不応期を管理する `AutomaticBlink`。
- `behavior/blink.*`：選択済みの単発・二連を時刻から進める `Blink` アニメーション。乱数や身体状態の管理を含みません。
- `touch/touch_sensor.*`：3電極の測定・診断ログを所有する独立タスク。保持状態と撫でイベントを身体タスクへ渡します。
- `touch/petting_detector.*`：確定接触の順序と時間から両方向の撫でを認識する、ハードウェア非依存の検出器。
- `touch/contact_detector.*`：ハードウェア非依存の起動時校正・ヒステリシス・継続時間判定。
- `board/amoled.c`：確認済みRev2.0のI2C、TCA9554のEXIO0リセット、QSPI、DMA転送。
- `display/eye_renderer.*`：ハードウェアに依存しないC++描画。`EyeState`で視線・開き具合・瞳の大きさを指定。

UI部品は不要なので、LVGLを導入せずRGB565を直接生成しています。画像の切り替えではなくパラメータで描画します。

## Makefileでのビルドと書き込み

リポジトリのルートから実行します。ESP-IDF v5.5.6を使用し、既定では `~/esp/esp-idf/export.sh` を自動的に読み込みます。

```bash
make build
make install PORT=/dev/ttyACM0
make monitor PORT=/dev/ttyACM0
```

`make install` は必要なビルドを行って実機へ書き込みます。ホストPCへのインストールではありません。`make flash` も同じ動作です。`PORT` はデモで使用したポートへ置き換えてください。既存のアプリケーションは書き換わります。モニター終了は `Ctrl+]` です。

```bash
make build IDF_PATH=/path/to/esp-idf
make install PORT=/dev/ttyACM0 BAUD=460800
make menuconfig
make test
```

対象はESP32-S3に固定しています。`sdkconfig.defaults` は16MB Flash、Octal PSRAM、USB Serial/JTAGコンソールを指定します。生成済みの `sdkconfig` がある場合、defaults変更は既存値を上書きしません。`make menuconfig` で確認してください。物理容量と実機の認識結果は起動ログで照合します。

初回ビルドではコンポーネントレジストリへの接続が必要です。直接依存は `main/idf_component.yml`、解決済みの依存関係は `dependencies.lock` に記録しています。`build/`、`managed_components/`、生成される `sdkconfig` はGit管理対象外です。

## 瞬きと表示更新

瞬きと表情の仕様は[身体反応モデル](../../docs/step1-body-behavior.md)を正とします。瞬きは身体状態から独立した自動運動で、ワイブル分布に従って発生します。時間定義・状態更新・入力検証規則も同文書に集約しています。

振る舞いは10msごとに時刻を確認し、待ち時間を内部に持たず開き具合を返します。表示タスクには長さ1のキューで最新状態のみ渡すため、古いフレームが溜まりません。DMA待機は表示タスクに限定し、将来の入力処理と独立させています。描画・転送が遅れた場合は途中のフレームを省略します。表示は約20ms周期（50fps目安、RTOSのtick単位で丸め）を目標にします。実測値は `eyes_perf` ログの `render_avg`（描画）、`transfer_avg`（転送待ちを含む）、`work_max`（1フレーム処理の最大時間）にマイクロ秒で表示します。アイドル時間を除いた処理時間であり、パネルの実測FPSではありません。20,000µsを超えると目標周期に間に合いません。

通常は丸い白目と瞳を表示します。閉眼中は白目を縦に閉じ、黒い瞳をその輪郭でクリップします。閉じ切ったときは黒背景になります。初回だけ背景全体を消去し、その後は両目と目の間を含む固定矩形を更新します。両目をバッファへ描き終えてから1回の描画要求で転送します。円の平方根は輪郭の1pxだけに限定し、ほかは二乗距離と行・列ごとの事前計算で判定します。快のまぶた曲線は横座標ごとに1回だけ平方根を計算します。

両目をまとめた転送によって描画途中の状態や左右更新の時間差を抑えます。パネルのTE信号に同期していないため、画面走査とのずれによるティアリングを完全に除去する保証はありません。ちらつく場合は、処理時間ログと実機映像を基に切り分けます。

## 快の表情

ユーザーによる実機確認済みの、上下の弧を揃えたまぶた形状を採用しています。[形状と追従の仕様](../../docs/step1-body-behavior.md#採用した快のまぶた形状)を参照してください。

実際の身体状態から表情を更新し、瞬きを継続します。電極Aの接触が保持刺激となり、快が増すと目を細めます。ホストテストでは意味イベントを注入して検証します。

上下のまぶたは同じ楕円弧を上下移動して作り、円形の白目と瞳をクリップします。外周では元の円によるクリップが残るため、端の厚みまで一定とは限りません。初期値の最大快では標準サイズの瞳が覆われます。`squint_strength=0.5`、表情追従の時定数200msを維持しています。

`make test` は通常・最大快・微小な変化・上下の弧の間隔・視線端・瞳サイズ変更・実際の瞬き行動での消去と復帰・快の自然減衰を検証します。自動運動の確率・不応期・平均開始間隔も検証します。転送矩形・DMA方式・表示ドライバーは変更していません。実機の処理時間は `eyes_perf` ログで確認してください。ホスト測定では新形状は通常描画の約1.2倍でしたが、ESP32上の描画時間は未測定です。

## 表示初期化の根拠と差分

ユーザーが表示成功を確認したローカル公式サンプル：

`~/esp/ESP32-S3-Touch-AMOLED-2.41-V2/02_Example/ESP-IDF/09_LVGL_V9_Test`

基板定義・初期化コマンドは、Waveshare公式リポジトリのコミット `0eaf16cfae3440d445f2b6caa71e94065094551f` の `components/main_config/main_config.h` と `components/lcd_bsp/display_bsp.c` を根拠にしています。[公式ソース](https://github.com/waveshareteam/ESP32-S3-Touch-AMOLED-2.41-V2/tree/0eaf16cfae3440d445f2b6caa71e94065094551f/02_Example/ESP-IDF/09_LVGL_V9_Test)。

- ネイティブ座標450×600に、論理座標600×450をソフトウェアで90度回転して送ります。パネルを横向きに置いてください。取り付け方向によっては180度の調整が必要です。
- 公式のQSPI 40MHz、RGB565、コマンド表、EXIO0のリセット順序を維持します。画面タッチ用EXIO1は操作しません。
- 初期化時の輝度を0にして、背景と目を描いた後に約50%へ上げます。
- RGB565は上位バイトから送信します。内部DMAバッファは両目を含む186×476画素の177,072バイトで、転送完了後に再利用します。初期化失敗・転送タイムアウトはログを伴って停止します。
- 起動時のリセット待機は表示タスク内に限定します。
- Wi-Fi、BLE、画面タッチ、IMU、RTC、microSDは初期化しません。表示リセットに必要な共有I2Cバスは使用します。

## 電極Aの初期動作確認

Step 1.3では外部電極A/B/Cを測定し、保持と両方向の撫でを身体反応へ接続します。B/Cは各510Ωを介してハードウェア文書の割り当て表どおりに配線してください。配線の正本は[ハードウェアの電極A配線手順](../../docs/hardware.md#step-13初期確認電極aだけの配線)です。画面タッチのFT6336とは別の機能です。

### ドライバーと処理構成

ESP-IDF **v5.5.6** の新ドライバー `esp_driver_touch_sens` / `driver/touch_sens.h` を使用します。実際の同バージョンのヘッダー、ドライバー実装、および[公式touch_sens_basicサンプル](https://github.com/espressif/esp-idf/tree/v5.5.6/examples/peripherals/touch_sensor/touch_sens_basic)と[共通設定](https://github.com/espressif/esp-idf/blob/v5.5.6/examples/peripherals/touch_sensor/touch_sens_examples_common/touch_sens_example_config.h)を参照しています。旧 `touch_pad` APIとは混在させません。

- 独立した `touch_raw` タスク（優先度5、スタック4096バイト）がコントローラーとA/B/Cの3チャンネルを所有します。表示タスクは優先度4のままです。
- 50ms周期で `touch_sensor_trigger_oneshot_scanning` を実行し、完了後に `touch_channel_read_data(..., TOUCH_CHAN_DATA_TYPE_RAW, ...)` で読みます。最初の成功3測定はウォームアップとして捨てます。
- 測定待ちは専用タスク内だけで、3チャンネル全体に100msのタイムアウトを設けます（スケジューリングによる超過はあり得ます）。描画より優先度を高くし、ドライバーのチャンネル間の再開遅延を抑えます。走査中の待機はドライバーがCPUを譲ります。過去の測定をまとめて再生しません。コールバックやISR内ではログを出しません。
- 測定設定は公式V2サンプルと同じ充放電500回・電圧範囲0.5〜2.2V・充放電速度7を初期値とします。測定感度の最終調整値ではありません。
- ドライバー内のフィルターと接触イベントは使いません。API構造体の `active_thresh` はゼロ初期化のままで、接触判定には使用しません。ソフトウェア側の判定は下記の暫定設定で行います。
- 初期化失敗は失敗したAPI名・エラー名をログに出し、診断だけを終了します。チャンネル固有のエラーは `touch_a` / `touch_b` / `touch_c` で識別します。測定・読み取り失敗は正常値を出さず、次の周期で再試行します。`ESP_ERROR_CHECK` による本体停止は行いません。
- 測定値をBodyBehaviorやEyeRendererへ渡しません。基準値・接触状態・ウォームアップ・継続時間・ログ間隔は各電極が独立して保持します。走査全体の失敗は全電極の欠落、読み取り失敗は該当電極だけの欠落として扱います。判定には走査完了時刻を使います。

### 接触判定（暫定・電極A単独で実機確認済み）

`touch/contact_detector.h` の `ContactSettings` に共通の暫定調整値を集約しています。Aで試した設定をB/Cにも暫定適用します。基準値は各電極で独立して取得し、B/Cの感度は実測で判断します。基準値は起動後の成功40測定以上・約2秒以上の平均です。最初の3成功測定を捨てた後に校正します。**起動から `event=calibrated` までは触れないでください。** 校正区間の最大値−最小値が500を超える、または0を含む場合は警告して再取得します。測定エラー・150msを超える欠落も校正をやり直します。

- 接触：`raw - baseline >= 1000` が100ms継続。
- 離脱：`raw - baseline <= 600` が100ms継続。
- その間は確定状態を維持します。条件を外れた値・測定エラー・150msを超える欠落で継続時間判定を中断します。欠落自体を離脱とは扱いません。
- 校正後は電極ごとに非接触時の緩やかなドリフトへ追従します。条件・制限は[基準値の追従](../../docs/step1-body-behavior.md#基準値の追従暫定)を参照してください。大きくずれた場合の再校正は、手を離してRESETします。
- 通常ログは250ms周期、校正完了・接触開始・終了は直ちにログへ出します。身体タスクは最新の確定接触状態の変化を `touch_started` / `touch_ended` に変換してBodyBehaviorへ渡します。

暫定閾値は初期測定での約2,000以上の増加と非接触時の揺れを参考にしたものです。試した短い接触は操作と一致しています。環境・電極条件を変えた感度は未検証です。安定して触れたまま起動すると、その値を非接触基準として採用する可能性があり、raw値だけでは識別できません。`state=calibrating` 中のbaseline/deltaは判定用の有効値ではありません。

### 3電極から表情への接続

`PettingDetector` が接触順序を意味イベントに変換し、身体タスクが保持と撫でを `body.input()` に渡します。判定条件・キュー・欠落の扱いは[タッチ入力と撫で判定](../../docs/step1-body-behavior.md#タッチ入力と撫で判定暫定)を正本とします。瞬き・身体モデル・描画計算は維持しています。

3電極とも校正完了後、いったん全部離し、A→B→Cを約0.4〜1.5秒でなぞってください。最後まで手のひらで覆わず、指を移動させます。毎回全電極から手を離し、逆方向も試します。ログ例（実測結果ではありません）：

```text
touch: elapsed_ms=... event=petting_detected direction=A->B->C
body: petting_detected direction=A->B->C valence=...
```

撫で1回で快が加算されて目が細まり、離した後にゆっくり中立へ戻ることを確認します。3枚同時に手を置いても撫でログが出ないこと、保持中も瞬きが続くことを確認してください。保持状態の変化は `body: touch holding=1/0` で確認できます。保持だけでも徐々に快が増えるため、表情変化だけで撫で成立を判断しないでください。速すぎる撫では接触の100ms確認を満たせず取り逃がす可能性があります。

### 書き込み・測定の基本手順

1. 電源を切り、ハードウェア文書に従って電極A/B/Cを配線します。机上で板とワイヤを固定してください。
2. USB-CをPCへ接続し、リポジトリのルートから実行します。ポート名は実際のデバイスに合わせます。

   ```bash
   make install PORT=/dev/ttyACM0
   make monitor PORT=/dev/ttyACM0
   ```

   WSLでUSB接続が必要なら、対話可能な端末で `bash bin/connect-esp32.sh` を実行します。sudoのパスワード入力には端末が必要です。モニター終了は `Ctrl+]` です。

3. 起動時の `touch_a` / `touch_b` / `touch_c` 設定ログと `Warmup complete` を確認し、3枚とも手を離したまま各電極の `event=calibrated` を待ちます。表示と通常の瞬きも続いていることを確認してください。
4. 指や手を電極・ワイヤから離して10秒程度観察し、`raw` の範囲と揺れを記録します。
5. 板の表面の、裏側の電極Aに対応する位置へ指を置き、5〜10秒保持します。銅箔へ直接触れず、配線や基板も動かさずに測定してください。
6. 手を離して10秒観察し、接触・非接触を数回繰り返します。B/Cでも同じ試験を行い、触れていない隣の電極が反応しないことも確認します。接触ごとに `touch_started`、離脱ごとに `touch_ended` が各1回だけ出るか確認します。
7. 軽い接触、30秒程度の長押し、非接触で1分以上放置を試します。長押し中に離脱が出ないこと、放置中に接触が出ないこと、保持で表情が変化し、瞬きが継続することを確認してください。閾値付近で揺れる場合はraw・baseline・deltaを保存します。

ログの形式（山括弧内は説明用のプレースホルダーで、実測値ではありません）：

```text
I (...) touch_a: elapsed_ms=<ミリ秒> raw=<測定カウント> baseline=<基準値> delta=<差> state=<idle/touched/calibrating> event=<none/calibrated/touch_started/touch_ended>
E (...) touch: elapsed_ms=<起動からのミリ秒> scan failed: ESP_ERR_TIMEOUT (0x107)
```

`raw` は容量のpF表示ではなく、充放電にかかる時間に対応したカウントです。ESP32-S3では通常、接触で容量が増えると値が増える方向ですが、絶対値と変化量は実測で確認します。エラー例は形式の説明であり、発生を予測するものではありません。rawを含む通常ログは測定API成功時のみ出力します。接触判定の正確性は実機で照合してください。

### 値が変化しない・不安定な場合

- `touch_a` が出ない場合は起動ログとタスク作成・初期化エラーを確認し、書き込んだファームウェアとポートを確認します。
- エラーが出る場合はAPI名・エラー名と起動ログを記録します。初期化に失敗した場合は原因を解消してRESETします。
- 電源を切って、J8の向きと3番、抵抗両端のブレッドボード接続列、銅箔と金属ピンの接触を確認します。テスターがあればGPIO側ワイヤから電極まで約510Ωとなるか確認します。
- 非接触と接触の差が小さい場合は、板厚・電極面積・接触位置を記録し、一つずつ条件を変えて比較します。ワイヤを短くして固定し、USBやディスプレイ周囲の配線から離します。
- 0や一定の値が続いても、それだけで「非接触」とは判定しません。GPIO1が別機能に使われていないか、配線・測定設定・起動エラーを確認します。
- 大きく揺れる場合は、ジャンパ接触・電源・手や配線の位置を固定して再測定します。`eyes_perf` と身体更新遅延の警告も確認し、ログ追加による表示への影響を観察してください。

電極寸法・板厚・配線長・電源条件と、非接触／接触／離した後のログを保存してください。初期測定の結果は下記の確認状況を参照してください。条件を変えた検出感度、長時間の安定性、エラー時の実機挙動は未確認です。撫で判定とB/Cの実機検証は残っています。

## ホスト側テストとプレビュー

`make test` はESP-IDFや実機なしで、既存の描画検証、瞬きの時系列、身体状態・刺激・確率・表情合成・不応期・身体状態と瞬きの独立性を検証します。同一シードとイベント時刻では、呼び出しの分割が異なっても内部状態と行動時刻が一致することを確認します。シミュレーションは下記条件で自動実行します。

### 7項目の設定とイベント注入

`behavior/body_behavior.h` の `BehaviorParameters` が7項目の既定値を持ちます。意味と初期値の一覧は[仕様書のパラメータ表](../../docs/step1-body-behavior.md#調整可能な振る舞いパラメータ)に集約しています。実機では `app_main.cpp` の `parameters` を変更して再ビルドします。時間の単位はすべて秒です（150msは `0.150f`）。例えば：

```cpp
utsushimi::BehaviorParameters parameters;
parameters.holding_sensitivity = 0.03f;
ESP_ERROR_CHECK(parameters.valid() ? ESP_OK : ESP_ERR_INVALID_ARG);
utsushimi::BodyBehavior body({[](void *) { return esp_random(); }, nullptr}, parameters);
```

入力範囲と正の待機時間の制約は[発生確率モデル](../../docs/step1-body-behavior.md#発生確率モデル)を参照してください。`app_main.cpp` は構築前の `parameters.valid()` を `ESP_ERROR_CHECK` で検査します。ライブラリを直接利用する場合も検査し、既定値へのフォールバックは `used_default_parameters()` で検出してください。実行中の設定変更・保存UIはありません。

ホスト側では固定シードの乱数コールバックを注入します。テストの `Rng` は非ゼロシードのxorshift32です。実機は `esp_random()` を使用しますが、暗号用途には使いません。乱数コールバックは必須で、一様な32bit値を返す契約です。

```cpp
body.advance(elapsed_us);  // 前の入力から現在まで進める
body.input(utsushimi::BodyEvent::touch_started);
body.input(utsushimi::BodyEvent::petting_detected);
// 継続保持中はadvance()だけで快方向の刺激が続く
body.input(utsushimi::BodyEvent::touch_ended);
eyes.openness = body.blink_openness();
eyes.upper_lid = eyes.lower_lid = 1 - body.expression_openness();
```

イベントは呼び出し時点のモデル時刻で適用します。同じタスクから呼ぶAPIであり、スレッドセーフではありません。3電極の保持状態と撫でイベントを身体タスクがこのAPIへ渡します。描画側へセンサー値は渡しません。

### 瞬きの統計検証

尺度は[仕様書の理論式](../../docs/step1-body-behavior.md#発生確率モデル)から算出し、経験的な係数調整は行いません。既定値の尺度は4.316050314秒です。`make test` が次の再現可能な検証を実行します。

- xorshift32の独立シード9001〜9008、各10,000個、計80,000個の完全な開始間隔。起動から最初の瞬きまでの区間は含めません。
- 呼び出し周期5 / 10 / 20 / 37msを各2試行。内部刻みは共通の10msです。
- 二連内部の2回目を別行動とは数えません。各間隔から直前の実際の動作長と不応期を引いた待機時間を、連続ワイブル分布と比較します。
- 許容誤差：全体平均5秒±0.10秒、各試行±0.15秒。二連率は全体10%±1ポイント、各試行±1.5ポイント。
- 分布の最大CDF差（KS統計量）は全体0.015未満、各試行0.03未満。乱数のばらつきと10ms量子化を許容する回帰テストです。

実測結果は確認状況に記載します。標準出力には各試行の観測時間・平均・標準偏差・二連率・KS統計量、全体の待機時間分位点を出します。同一シードでの呼び出し刻みの再現性、快・保持の有無による瞬き系列の一致、長時間休止の上限処理、設定境界値も単体テストします。ホストとESP32間の浮動小数点演算のビット一致は保証しません。

実機の `body` ログは累積動作数・二連数・最後の開始モデル時刻・快不快を出します。休止時間を捨てるとモデル時刻と壁時計がずれるため、警告のない通常動作区間で間隔を評価してください。

### 表情描画中の測定タイムアウトの確認

3電極版のユーザー提供ログでは、C接触後の連続表情更新中に走査タイムアウトが連続し、500msの鮮度切れで保持が解除されています。優先度・期限の設定は上記のとおりですが、この設定での実機再検証は未完了です。閾値や撫で判定条件は変更していません。

再書き込み後、各電極を10秒程度保持し、表情変化中もrawログが継続することを確認します。その後両方向の撫でを試します。タイムアウトが残る場合は `Scan failures=... scan_us=... timeout_ms=...`、成功に戻った際の `Scan recovered ...`、`Slow scan` と `eyes_perf` を含むログを保存してください。`scan_us` は待機・実行待ちを含むAPI呼び出し時間で、電極そのものの測定時間ではありません。描画負荷との関連は疑われますが、原因の確定と解消確認は実機試験を要します。

基準値追従の実機確認では、手を離して起動・校正した後に10分程度放置し、各電極のbaselineとdeltaを観察します。その後、個別の接触・30秒以上の長押し・離脱・両方向の撫でを確認してください。長押し中にbaselineが動かず、放置中に誤接触が起きないことが確認点です。追従の時間条件は暫定です。ユーザーから実機で良好との報告がありますが、試験時間・残差の定量評価と環境を変えた再現性は未確認です。ユーザー報告では接続修正後に撫でへの反応を確認していますが、高速な撫では取り逃がす場合があります。
